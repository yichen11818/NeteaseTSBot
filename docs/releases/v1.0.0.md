# v1.0.0 · 多服务器独立播放，正式迈入 1.0

这是一次重大更新，汇总 **v0.8.0 至 v1.0.0 的全部改动**。同一个项目现在可以同时连接多台 TeamSpeak 3 / 6 服务器，并通过一个 Web 控制台切换管理；各台服务器独立播放，各自保存队列、音量、频道、身份和账号配置。

## 多服务器：一个项目，一个控制台

- 新增 `servers.json` 服务器清单和 `scripts/multi_server.py` 部署生成器，一次生成统一的 Docker Compose 项目。
- 每台服务器拥有独立的 backend / voice-service、数据库、上传资源、音频临时卷、身份、状态文件及容器网络。三个服务镜像各构建一次，由各组复用。
- Web 顶部新增服务器切换器；登录页和错误页也可切换。每个服务器都有独立的 `/s/<id>/` 页面和 `/api/servers/<id>/` API 路径，不同标签页可以同时管理不同服务器。
- 管理员 Cookie 按名称及路径隔离；切换不会停止原服务器播放，也不会把上一台服务器的请求和 CSRF 状态带到下一台。
- 音质偏好和“我喜欢的”缓存按服务器隔离。本地收藏、搜索历史和主题继续作为浏览器个人偏好共享。
- 新增服务器通过清单及生成器完成，进入 Web 后配置该服务器的地址、频道和音乐账号；本版不提供网页内直接创建容器或机器人实例的功能。

对应多机器人需求 [#18](https://github.com/yichen11818/NeteaseTSBot/issues/18)，并回应历史讨论 [#5](https://github.com/yichen11818/NeteaseTSBot/issues/5)、[#6](https://github.com/yichen11818/NeteaseTSBot/issues/6) 中的多实例切换需求。

## 播放稳定性、恢复策略和音质

- 新增控制台“播放恢复”设置：可配置自动恢复、重试次数和间隔、重试耗尽后跳过或等待，以及连续失败后的冷却策略。故障期间保留队列，关闭恢复后取消待执行的恢复任务。对应 [#24](https://github.com/yichen11818/NeteaseTSBot/issues/24)，实现于 [#26](https://github.com/yichen11818/NeteaseTSBot/pull/26)。
- 网易云和 QQ 音乐可分别设置服务器默认请求音质，前端可跟随当前服务器或选择自己的音质偏好。请求音质仍受音乐平台资源和账号权限限制。对应 [#25](https://github.com/yichen11818/NeteaseTSBot/issues/25)，实现于 [#27](https://github.com/yichen11818/NeteaseTSBot/pull/27)。
- 修复网易云自动音质遇到特定风控错误时的标准音质回退。对应 [#20](https://github.com/yichen11818/NeteaseTSBot/issues/20)、[#22](https://github.com/yichen11818/NeteaseTSBot/pull/22)。
- 修复解码 PCM 预缓冲无限积累的问题：使用有界通道和背压，满时让解码器等待，不截断歌曲、不丢弃音频帧。当前 Linux 缓冲为 50 帧（约 1 秒），Windows 为 200 帧（约 4 秒）。
- 修复播放结束事件发出前的旧状态清理，避免残留播放状态干扰自动续播；修复声场宽度为 `0` 时被错误转换的问题。
- 修复 B 站缓存限制在重启后没有使用已应用设置的问题，并补充 Windows UTF-8 配置测试。

[#28](https://github.com/yichen11818/NeteaseTSBot/issues/28) **部分完成**：内存预缓冲的有界化已经纳入本版；Issue 中提出的控制台可配置缓冲秒数尚未实现，不能将本版描述为完成了该 Issue 的全部需求。

## 聊天点播与 TS6 等级系统

- 支持通过 `歌单 id:<ID>` / `playlist id:<ID>` 直接导入网易云歌单；纯数字关键词仍保留搜索语义。对应 [#21](https://github.com/yichen11818/NeteaseTSBot/issues/21)、[#23](https://github.com/yichen11818/NeteaseTSBot/pull/23)。
- 支持在 TeamSpeak 聊天中通过 `b站 <BV号或链接>` 立即播放，或 `点播b站 <BV号或链接>` 加入队列，复用现有时长限制、缓存与播放流程。
- 新增可选的 TS6 在线时长等级系统，通过 WebQuery 统计累计时长并同步专用等级组；默认关闭，并包含受保护组、机器人和 AFK 排除、配置校验及持久化处理。相关实现与审查见 [#19](https://github.com/yichen11818/NeteaseTSBot/pull/19)。

## 鉴权、日志与部署

- 为共享 QQ 音乐登录路由补齐管理员登录和 CSRF 保护，避免未授权访问登录流程。
- 从 QQ 音乐应用日志中移除凭据内容。
- 默认 Docker Compose 不再向宿主机发布未认证的 Voice gRPC 端口；后端通过容器网络连接 Voice。
- 修复后端镜像在安装 Playwright 浏览器依赖前因缺少 `libatomic.so.1` 而失败的问题。对应 [#30](https://github.com/yichen11818/NeteaseTSBot/issues/30)、[#31](https://github.com/yichen11818/NeteaseTSBot/pull/31)。
- Rust 检查与 Linux 发布包构建使用系统 Opus 依赖；补充多服务器 Compose / Nginx 配置检查。
- Linux amd64 发布包现在包含完整的 Git 跟踪源码、Dockerfiles、多服务器生成器、示例和文档，并附带编译好的 Voice 二进制与 Web 产物。环境文件、数据库和本地实例数据不进入发布包。

## 开始使用与升级

已有单服务器的启动方式继续保留。升级前备份 `tsbot.env`、数据库、`data/`、日志中的身份及状态文件，并继续使用原来的 `TSBOT_COOKIE_KEY`。建议三个服务同步升级。

单服务器预构建镜像升级：

```bash
TSBOT_IMAGE_TAG=v1.0.0 docker compose -f docker-compose.prebuilt.yml pull
TSBOT_IMAGE_TAG=v1.0.0 docker compose -f docker-compose.prebuilt.yml up -d
```

多服务器从本版源码或完整发布包创建（Windows 可使用 `Copy-Item`）：

```bash
cp servers.example.json servers.json
# 编辑服务器 ID 和显示名称
python scripts/multi_server.py --init-env
docker compose -f docker-compose.multi.json config --quiet
docker compose -f docker-compose.multi.json up -d --build
```

生成器需要 Python 3.10+，只使用标准库。此多服务器流程使用本地源码构建，不能仅切换旧单服务器 Compose 的镜像标签来启用。

新增实例的初始密码分别位于 `instances/<id>/logs/initial-admin-password.txt`；登录后在当前服务器的系统配置中填写 TeamSpeak 地址、频道及音乐账号。迁入旧数据库时，应核对持久化的 Voice 地址，并改为该实例的 `voice-<id>:50051`。

默认不再发布 `50051`。确需本机调试时使用 `docker-compose.voice-debug.yml`，仅绑定回环地址。完整部署、增加实例和迁移步骤以 [HOWTOSTART.md](https://github.com/yichen11818/NeteaseTSBot/blob/v1.0.0/HOWTOSTART.md#一个项目连接多个-teamspeak-服务器) 为准。
