# TeamSpeak 聊天点播 Bilibili

在机器人接收聊天消息的频道或聊天范围内发送：

- `b站 BV1xx411c7mD`：立即播放视频音频，会替换当前播放请求。
- `点播b站 BV1xx411c7mD`：加入现有播放队列，不主动切换当前歌曲。
- `b站 https://www.bilibili.com/video/BV1xx411c7mD/`：完整视频链接。
- `点播b站 https://www.bilibili.com/video/BV1xx411c7mD/?share_source=copy`。

支持可选 `!` 前缀及 TeamSpeak 的 URL 标记。暂不支持 b23.tv 短链、av 号和分 P 选择；
链接的查询参数不参与选集，沿用现有解析器的默认视频音频。
BV 号先检查格式，再通过现有元数据解析验证是否可访问。
视频时长限制、音频下载缓存及实际播放均复用现有 Bilibili 后端功能。
队列中的视频在实际播放时才下载音频，入队成功不表示届时仍可访问。

解析和播放请求由后台任务执行，同时最多保留 4 个待处理请求；繁忙时提示稍后重试。
失败时返回中文提示，不把底层异常、Cookie 等内部信息发送到聊天。
聊天命令继承现有 TS 聊天入口的访问范围，当前项目没有按 TS 用户角色授权点歌的规则。
这两条指令不新增 HTTP 接口，也不绕过 HTTP API Token 去调用管理路由。

## 部署

更新后端源码并按现有方式重启后端即可。无需新增依赖、数据库迁移或环境变量；
无需更改 Docker、Rust voice 服务或等级配置。保留现有 Bilibili 网络访问和登录配置。
本次开发未自动提交、推送或部署。

验证：安装项目现有后端依赖后运行 `python -m unittest discover -s tests`。
测试使用模拟外部服务，不连接真实 TS 或 Bilibili 服务器。
